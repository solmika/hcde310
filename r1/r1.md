## What it is + why a designer might care

I chose the API from TheMealDB, which provides various meal recipes from around the world. Each meal has a name, its category, the cuisine, and ingredients. I think designers might care about TheMealDB because it provides access to real recipes from different countries and meal images designers can work with. TheMealDB can filter meals by main ingredient and category, as well as search for meals by the first letter. For example, the filtering by main ingredients feature could help create an app for students on a low budget to find meals easily by searching for the main ingredient they have.

## Setup
For setup, I needed to install requests (pip install requests) before running the program to get an API response. For auth, I didn't need to sign up for a key because TheMealDB already had a free test key 1 in the URL -- 
https://www.themealdb.com/api/json/v1/1/filter.php. The endpoint in the URL is filter.php, so my program can find the names of meals by the cuisine typed.

## Working example
```python
import requests

term = input("Enter a meal's cuisine: ")

url = "https://www.themealdb.com/api/json/v1/1/filter.php"
params = {"a": term}
response = requests.get(url, params=params)


if response.status_code == 200:
    data = response.json()
    #when just putting print(data) it prints the whole dictionary
    if data["meals"] is None:
        print("No result. Please try again.")
    else:
        for i in data["meals"]:
            print(i["strMeal"])
else:
    print("Request failed:", response.status_code, response.reason)
 ```


The output depends on what cuisine the user types into the input(Enter a meal's cuisine: ). I typed Ukrainian.

## Gotchas
During testing, I typed a random word that isn't a cuisine. The program crashed (TypeError: 'NoneType' object is not iterable), so I needed to add an if/else statement with a None check for it to display the helpful message if the API finds no meals for the typed cuisine. Also, the TheMealDB docs were a little bit confusing. I couldn't find any information about the rate limits because TheMealDB doesn't publish them. They didn't show what the parameters represent, but I could find that parameters are listed as "a" for a cuisine, "i" for main ingredients, and "c" for a category. It would be great if they included it in their docs as well.
Finally, if you want to release an app using TheMealDB's API in an app store, for example, you need to become a paid supporter (about $10 for lifetime).

## Design angle
Making an app that can filter different meals for the day with the ingredients a student has at home, and make an option to choose the cuisine. This app would help students on a low budget who want to cook varied food. 

Ethical or UX consideration: 
If a person chooses a cuisine for their meal, some cuisines in the search do not have many meals. So, it could seem like one country doesn't have that many meals to offer. It would be helpful to add clarifying text, such as "Showing 7 recipes from TheMealDB", so it is clear that this is what TheMealDB has, not a representation of any cuisine.
